# 06 · 面试高频自测

> 每题都能在本项目里找到可运行的证据，建议先自己答，再跑对应用例验证。

---

## 一、基础

**1. 线程和进程的区别？**
进程是资源分配单位，线程是调度单位；同进程线程共享堆和方法区，各自有栈和程序计数器。

**2. 线程有哪几种状态？**
NEW / RUNNABLE / BLOCKED / WAITING / TIMED_WAITING / TERMINATED（`basic-02`）。
重点：等 `ReentrantLock` 是 WAITING 不是 BLOCKED。

**3. start() 和 run() 的区别？**
`start()` 由 JVM 创建新线程执行 `run()`；直接调 `run()` 就是普通方法调用，还在当前线程（`basic-03`）。

**4. 为什么 Thread 不能 start 两次？**
内部 `threadStatus` 只允许从 NEW 迁移一次，第二次抛 `IllegalThreadStateException`。

**5. sleep 和 wait 的区别？**
sleep 属于 Thread，不释放锁，到点自动醒；wait 属于 Object，必须在 synchronized 内，释放锁，需要 notify 唤醒。

**6. 怎么停止一个线程？**
`interrupt()` + 标志位，任务自己检查并退出；`stop()` 已废弃（`basic-04`、`pattern-06`）。

**7. 中断标志什么时候会被清除？**
抛出 `InterruptedException` 时清除；`Thread.interrupted()` 也会清除；`isInterrupted()` 不会。

## 二、JMM

**8. 说说 JMM。**
定义线程与主内存的交互规则，保证原子性、可见性、有序性。

**9. volatile 的作用？**
保证可见性、禁止重排序；不保证原子性（`basic-11`）。

**10. 为什么 DCL 单例要加 volatile？**
`new` 分三步（分配 / 初始化 / 赋值），没有 volatile 时可能拿到半初始化对象。

**11. happens-before 有哪些规则？**
程序顺序、监视器锁、volatile、start、join、interrupt、finalize、传递性（`basic-09`）。

**12. i++ 是原子操作吗？**
不是，读-改-写三步，并发下丢更新（`basic-07`）。

**13. 怎么保证可见性？**
volatile、synchronized/锁、final、并发容器、原子类。

## 三、锁

**14. synchronized 和 ReentrantLock 的区别？**
synchronized 自动释放、非公平、不可中断；Lock 可中断、可超时、可公平、多 Condition，但必须 finally unlock（`juc-07`）。

**15. synchronized 锁的是什么？**
实例方法锁 this，静态方法锁 Class，同步块锁括号对象（`basic-10`）。

**16. 锁升级过程？**
无锁 → 偏向锁（JDK15 废弃、18 移除）→ 轻量级锁（CAS 自旋）→ 重量级锁（阻塞）。

**17. 死锁的四个条件？怎么避免？**
互斥、占有且等待、不可剥夺、循环等待；统一加锁顺序、tryLock 超时、可中断锁（`basic-12`）。

**18. 读写锁的适用场景？**
读远多于写且读操作耗时；否则直接用普通锁或 volatile（`juc-08`）。

**19. StampedLock 的特点？**
乐观读 + 版本校验，读多写极少时性能好；不可重入。

## 四、线程池

**20. 线程池七个参数？**
core、max、keepAlive、unit、queue、threadFactory、handler（`juc-02`）。

**21. 线程池的执行流程？**
核心线程 → 队列 → 扩容到 max → 拒绝。**队列满了才扩容**。

**22. 为什么不建议用 Executors？**
固定池/单线程池用无界队列（OOM），CachedThreadPool 的 max 是 Integer.MAX_VALUE（`juc-03`）。

**23. 线程池大小怎么定？**
CPU 密集 N+1，IO 密集 N×(1+等待/计算)；或 Little's Law：并发 = QPS × RT（`juc-04`）。

**24. 线程池怎么优雅关闭？**
`shutdown()` → `awaitTermination(timeout)` → 超时 `shutdownNow()` 并记录丢失（`adv-04`）。

**25. submit 和 execute 的区别？**
execute 无返回值，异常走 UncaughtExceptionHandler；submit 返回 Future，异常被封装（`juc-01`）。

**26. 拒绝策略有哪些？**
Abort / CallerRuns / Discard / DiscardOldest；生产用 Abort + 降级，且必须打点（`adv-03`）。

**27. 线程池里任务抛异常会怎样？**
execute：线程打印堆栈后被替换；submit：异常进 Future，不 get 就静默（`adv-01`）。

## 五、并发工具

**28. CountDownLatch 和 CyclicBarrier 的区别？**
latch 一个等 N 个、一次性；barrier N 个互相等、可循环（`juc-11`）。

**29. Semaphore 和锁的区别？**
锁保护临界区且必须同一线程释放；Semaphore 限制并发数，可跨线程释放（`juc-10`）。

**30. ThreadLocal 原理？会内存泄漏吗？**
每个 Thread 一个 ThreadLocalMap，key 弱引用、value 强引用；线程池不 remove 会泄漏且串数据（`juc-16`）。

**31. ConcurrentHashMap 怎么保证线程安全？**
JDK8+ 数组 + 链表/红黑树，CAS + synchronized 锁桶头；`computeIfAbsent` 原子（`juc-14`）。

**32. CopyOnWriteArrayList 的优缺点？**
读无锁、迭代快照；写复制整个数组，写多性能差。

**33. CAS 的 ABA 问题？**
A→B→A 后 CAS 仍成功；用 `AtomicStampedReference` 加版本号（`juc-15`）。

**34. LongAdder 为什么比 AtomicLong 快？**
分段累加（base + Cell[]），分散竞争；`sum()` 是最终一致。

**35. ForkJoinPool 的工作窃取？**
每个线程一个双端队列，自己 LIFO，空闲线程从别人队尾 FIFO 偷任务（`juc-17`）。

## 六、异步与生产

**36. CompletableFuture 常用方法？**
supplyAsync / thenApply / thenCompose / thenCombine / allOf / anyOf / exceptionally / orTimeout（`juc-06`）。

**37. orTimeout 会停止任务吗？**
不会。它只让 Future 异常完成，底层任务继续跑（`adv-05`）。

**38. 怎么防止线程池被一个慢下游拖垮？**
超时 + 隔离 + 熔断 + 限流 + 降级（`adv-02`、`adv-08`）。

**39. ThreadLocal 怎么跨线程池传递？**
包装 Runnable（快照 + finally 清理）、TaskDecorator、TransmittableThreadLocal（`adv-06`）。

**40. 重试要注意什么？**
放大流量、必须退避 + 抖动、只重试可重试异常、保证幂等（`adv-07`）。

**41. 虚拟线程适合什么场景？**
IO 密集；不要池化；注意 synchronized pin；CPU 密集无优势（`juc-18`）。

**42. 线上 CPU 100% 怎么排查？**
`top -Hp` → tid 转 hex → `jstack | grep nid=0x...` → 看栈顶（`obs-05`）。

**43. 线程池满了有哪些信号？**
active == max、queue 高位、rejected > 0、RT 上升（`obs-02`）。

**44. 线程数持续增长怎么查？**
按线程名前缀聚合，找创建点；查 new Thread / 未 shutdown 的池（`obs-06`）。

## 七、手写题

**45. 用两个线程交替打印 1~100。**

```java
Object lock = new Object();
AtomicInteger counter = new AtomicInteger(1);

Runnable printer = () -> {
    boolean odd = Thread.currentThread().getName().equals("odd");
    while (true) {
        synchronized (lock) {
            // 没轮到我（奇偶不匹配）就等；注意必须 while，防虚假唤醒
            while (counter.get() <= 100 && (counter.get() % 2 == 1) != odd) {
                try {
                    lock.wait();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
            if (counter.get() > 100) {
                lock.notifyAll();
                return;
            }
            System.out.println(Thread.currentThread().getName() + ": " + counter.getAndIncrement());
            lock.notifyAll();
        }
    }
};

new Thread(printer, "odd").start();
new Thread(printer, "even").start();
```

条件等待的写法与 `pattern-03-guarded-suspension` 完全一致：`while` 包住 `wait`，醒来重新检查。

**46. 手写一个有界阻塞队列。**

一把 `ReentrantLock` + 两个 `Condition`（notFull / notEmpty），环形数组 + `while` 等待。
完整实现见 `juc-09-condition`。

**47. 手写一个线程安全的单例。**

静态内部类 / 枚举 / DCL（instance 必须 volatile），见 `basic-11`。

**48. 用 CompletableFuture 并行调用三个接口并聚合。**

```java
CompletableFuture<String> a = supplyAsync(this::callA, pool);
CompletableFuture<String> b = supplyAsync(this::callB, pool);
CompletableFuture<String> c = supplyAsync(this::callC, pool)
        .orTimeout(300, MILLISECONDS)
        .exceptionally(e -> "降级");
allOf(a, b, c).join();
return a.join() + b.join() + c.join();
```

见 `adv-11-parallel-aggregation`。
