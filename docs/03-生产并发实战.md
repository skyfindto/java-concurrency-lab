# 03 · 生产并发实战

> 对应用例：`adv-01` ~ `adv-12`
> 一句话：**并发代码能跑通只是及格线，能控制住才是生产可用。**

---

## 稳定性模型：六道防线

```
流量 → 限流 → 隔离 → 超时 → 熔断 → 降级 → 兜底数据
        ↑ 入口保护     ↑ 出口保护   ↑ 快速失败
```

| 防线 | 解决的问题 | 对应用例 |
|---|---|---|
| 限流 | 进来的太多 | `adv-08` |
| 隔离 | 一个下游拖垮全部 | `adv-02` |
| 超时 | 等待没有尽头 | `adv-05` |
| 熔断 | 下游挂了还在等 | `adv-08` |
| 降级 | 出问题也要有返回 | `adv-03` |
| 背压 | 生产快消费慢 | `adv-09` |

---

## 1. 线程池治理四件套

```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        8, 32, 60, TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(500),
        new NamedThreadFactory("order-pool"),   // ① 命名
        new MetricsRejectionHandler("order-pool")); // ② 拒绝打点
```

1. **命名**：`order-pool-3` 而不是 `pool-1-thread-3`（`adv-01`）；
2. **有界队列**：容量按延迟反推（`adv-09`）；
3. **拒绝策略 + 降级**：拒绝后返回缓存/默认值，绝静默丢弃（`adv-03`）；
4. **监控**：active / queue / completed / rejected 四指标（`obs-02`）。

**池子隔离**：核心业务、旁路任务、每个慢下游，都应该有独立的池（`adv-02` 实测延迟差 10 倍）。

## 2. 超时：任何一个等待都要有上限

```java
// 错误：无超时
future.get();

// 正确：超时 + 取消 + 降级
try {
    return future.get(800, TimeUnit.MILLISECONDS);
} catch (TimeoutException e) {
    future.cancel(true);
    metrics.timeout("inventory");
    return fallback();
}
```

**超时预算自上而下递减**：

```
网关 3000ms
  └─ 订单 2000ms
       ├─ 库存 800ms（可重试 1 次，单次 ≤ 400ms）
       └─ 优惠券 500ms（不重试）
```

**最大的坑**：`CompletableFuture.orTimeout` 只让等待方超时，**底层任务继续跑**，线程仍被占用（`adv-05` 有实测）。

## 3. 上下文传递

ThreadLocal 跨线程池一定会丢，因为执行任务的是另一个线程。

```java
Runnable wrap(Runnable task, String traceId) {
    return () -> {
        try {
            MDC.put("traceId", traceId);
            task.run();
        } finally {
            MDC.remove("traceId");
        }
    };
}
```

- Spring 用 `TaskDecorator` 统一注册；
- 存量代码用 TransmittableThreadLocal；
- **事务上下文不能跨线程**：异步任务里要写库，必须自己开事务；
- 上下文对象要小，别把整个 Request 塞进去。

## 4. 重试与幂等

```java
for (int attempt = 0; attempt < 3; attempt++) {
    try {
        return call();
    } catch (RetryableException e) {
        sleep(min(cap, base << attempt) + jitter());
    }
}
```

- 重试会**放大流量**：QPS 100、失败率 50%、重试 2 次 → 实际 175 QPS；
- 三层都重试 = 27 倍流量，必死；
- 只重试可重试异常（网络、5xx、429、DB 死锁），业务异常不重试；
- 非幂等写操作要重试，必须有唯一请求号 + 去重表。

## 5. 优雅停机

```java
// 1. 摘流量（注册中心下线 / K8s 标记 Terminating），等待 10s
// 2. 停止接收新任务
pool.shutdown();
// 3. 等待在途任务
if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {
    List<Runnable> dropped = pool.shutdownNow();
    log.error("强制停机，丢弃 {} 个任务", dropped.size());
}
// 4. 释放资源：连接池 / MQ consumer / 刷盘
```

| 方式 | 行为 | 结果 |
|---|---|---|
| `shutdown()` | 不接新任务，队列跑完 | 不丢任务 |
| `shutdownNow()` | 中断线程，返回队列 | 丢任务 |

Spring Boot：`server.shutdown=graceful` + `setWaitForTasksToCompleteOnShutdown(true)`。
K8s：`terminationGracePeriodSeconds` 要大于停机时间，配 `preStop` sleep。

## 6. 批量任务

```java
Semaphore permits = new Semaphore(4);           // 限并发
for (List<Item> batch : partition(items, 100)) { // 分批
    permits.acquire();
    CompletableFuture.runAsync(() -> {
        try { processBatch(batch); } finally { permits.release(); }
    }, batchPool);
}
```

要点：分批、限并发、单条失败隔离、失败明细可重跑、进度可观测、独立线程池。

## 7. 事务与一致性

- 事务绑定在当前线程的 Connection 上，**异步线程拿不到事务上下文**；
- 异步写库必须自己开新事务；
- 分布式事务：本地消息表 / 事务消息 / TCC，不要试图用线程解决一致性问题；
- 异步化之后，下游要能接受「最终一致」和「重复消息」（幂等消费）。

## 8. 常见故障与对策

| 现象 | 根因 | 对策 |
|---|---|---|
| 线程池打满 | 下游变慢 / 任务耗时增加 | 超时 + 隔离 + 熔断 |
| 队列堆积 OOM | 无界队列 | 有界 + 背压 + 拒绝 |
| 线程数暴涨 | 每次请求 new Thread | 线程池 / 虚拟线程 |
| 接口 RT 抖动 | 锁竞争 / GC | 缩小临界区、查 GC |
| CPU 100% | 死循环 / 正则 | 热点线程采样 |
| 任务静默失败 | submit 后不 get | handle 异常 + 监控 |
| 停机丢任务 | shutdownNow / daemon | 优雅停机 |
| 日志没有 traceId | 上下文未传递 | 包装器 / TTL |

## 9. 上线前问自己三个问题

1. **线程池满了会怎样？** —— 有拒绝策略吗？拒绝后降级了吗？有人被通知吗？
2. **下游挂了会怎样？** —— 有超时吗？会隔离吗？会熔断吗？
3. **停机会丢任务吗？** —— shutdown 了吗？awaitTermination 了吗？超时兜底了吗？

三个问题都能答上来，才叫「敢在生产用多线程」。
